Разборы

Case — рабочий контейнер одного расследования. В нём собираются SQL, EXPLAIN, результаты psql, статистика и заметки. Privacy scope задаёт общий mapping. Роль описывает сам artifact, а baseline/candidate сохраняются внутри конкретного comparison.

Как устроен разбор
1. Case Отдельное расследование конкретной проблемы или объекта. Case связан с PostgreSQL connection и privacy scope.
2. Inbox Рабочая папка case. Результаты из psql можно сохранять туда через \o и затем зарегистрировать как artifacts.
3. Artifacts SQL, EXPLAIN JSON, статистика, вывод команд и заметки, которые нужны для анализа проблемы.
4. Roles Роль описывает назначение самого artifact: query, plan, DDL/schema, reference, note и другие.

Case inbox

Это рабочая папка текущего case. Чтобы сохранить результат из psql: \o j.json → выполните запрос → \o → нажмите «Обновить inbox».

Новый файл

Встроенный редактор работает с локальными source artifacts до 2 MB. Inbox, share и generated artifacts остаются read-only.

Artifacts

Для SQL назначайте Query или DDL/schema, для EXPLAIN — Execution plan. Baseline/Candidate выбираются в конкретном сравнении и не меняют роль artifact. Shareable-файлы имеют lineage; artifacts, изменённые после comparison, помечаются STALE в истории.

Для чего нужны роли artifacts

SQL queryЗапрос или его вариант. Сторона baseline/candidate задаётся comparison.

Execution planEXPLAIN / EXPLAIN ANALYZE, который может участвовать в разных comparisons.

DDL / schemaОпределения VIEW, функций, индексов и других объектов.

ReferenceНастройки, статистика и вспомогательный технический контекст.

NoteЛокальные заметки по расследованию.

ComparisonОтдельная запись связывает artifacts как baseline/candidate и сохраняет историю экспериментов.
